# AI Calendar Assistant

An early-stage, command-line AI assistant that lets a user manage Google Calendar through natural-language conversations. It uses an OpenAI agent with Composio-provided Google Calendar tools and stores conversation turns in Supabase.

> **Project status:** Prototype / command-line application. The repository currently contains the agent, Composio setup, Supabase integration, SQL schema, and an environment-variable template. It is not yet a deployed web or mobile application.

## Overview

The goal is to make calendar interactions feel like chatting with an assistant rather than manually navigating a calendar interface.

Examples of intended requests:

- List upcoming calendar events.
- Check a schedule.
- Create calendar events from natural-language instructions.
- Update existing events.
- Delete events only after the user confirms.

The agent instructions in `agent.py` describe these capabilities. Actual execution depends on the Google Calendar tools available to the connected Composio session and the user's Google account permissions.

## How it works

1. The user enters a prompt in the command-line interface.
2. `agent.py` passes the prompt to the OpenAI Agents SDK using `Runner.run_sync()`.
3. The Calendar Assistant agent can use the Google Calendar tools exposed by Composio.
4. The agent's final response is printed in the terminal.
5. The prompt and response are inserted into the Supabase `chat_history` table.

### Architecture

```text
User (terminal)
     |
     v

     |
     v
OpenAI Agents SDK — Calendar Assistant
     |

agent.py
     |

```

### File responsibilities

#### `agent.py`

The main application entry point in the current implementation.

- Loads environment variables.
- Creates a Supabase client.
- Initializes Composio with the OpenAI Agents provider.
- Creates a session configured with the `googlecalendar` toolkit.
- Defines the `Calendar Assistant` agent and its instructions.
- Reads prompts in a continuous terminal loop.
- Stops when the user enters `exit` or `leave`.
- Sends each prompt to the agent and prints the final response.
- Saves each prompt and response to Supabase.

#### `main.py`

Contains a separate Composio setup/authorization flow.

- Initializes the Composio client.
- Creates a session for the `googlecalendar` toolkit.
- Starts Google Calendar authorization.
- Prints the authorization URL and waits for the connection to complete.
- Prints the connected account ID and obtains the session tools.

The current `agent.py` also creates its own Composio session. Review the authorization/session lifecycle to ensure the agent uses the intended connected Google account.

#### `database.sql`

Defines the conversation-history table:

| Column | Type | Purpose |
| --- | --- | --- |
| `id` | integer | Primary key |
| `created_at` | timestamptz | Record creation time; defaults to the current time |
| `query` | text | User's prompt |
| `response` | text | Agent's final response |

Current schema:

```sql
create table chat_history (
    id integer primary key not null,
    created_at timestamptz default now(),
    query text not null,
    response text not null
);
```

**Important:** The current Python insert does not provide an `id`. As written, the schema does not generate one automatically. Before relying on inserts, configure the primary key to generate values automatically, for example:

```sql
create table chat_history (
    id bigint generated by default as identity primary key,
    created_at timestamptz not null default now(),
    query text not null,
    response text not null
);
```

Use the corrected schema when creating a fresh table. If the existing table already contains data, use a carefully planned migration rather than dropping or recreating it.

#### `env.example`

Template for the environment variables used by the application:

```env
COMPOSIO_API_KEY=
OPENAI_API_KEY=
SUPABASE_URL=
SUPABASE_ANON_KEY=
```

Keep real credentials in a local `.env` file. Never commit `.env`, API keys, service-role keys, or other secrets.

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/foundedbycj/calendar.git
cd calendar
```

### 2. Create and activate a virtual environment

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

macOS / Linux:

```bash
source .venv/bin/activate
```

### 3. Install dependencies

The source imports the following Python packages/modules:

- `openai`
- `agents` (OpenAI Agents SDK)
- `composio`
- `composio_openai_agents`
- `composio_client`
- `dotenv`
- `supabase`

Install the corresponding packages using the installation instructions for the current OpenAI Agents SDK and Composio integrations. The repository does not currently include a pinned `requirements.txt`, so dependency versions are not locked.

### 4. Configure environment variables

Copy the template and fill in your own credentials:

```bash
cp env.example .env
```

On Windows PowerShell:

```powershell
Copy-Item env.example .env
```

Set:

- `OPENAI_API_KEY` — OpenAI API key.
- `COMPOSIO_API_KEY` — Composio API key.
- `SUPABASE_URL` — Supabase project URL.
- `SUPABASE_ANON_KEY` — Supabase anon/publishable key used by the current code.

Do not put credentials directly in source files or commit them to Git.

### 5. Configure Supabase

1. Open the SQL Editor in your Supabase project.
2. Run the schema from `database.sql` (prefer the identity-column version above for a fresh table).
3. Confirm that the table is named `chat_history`.
4. Ensure the key used by the application has the required insert permissions. If Row Level Security is enabled, configure an appropriate policy; do not disable security as a shortcut.

### 6. Authorize Google Calendar

Run the Composio authorization flow in `main.py` and complete the connection for the Google account you intend to use. Check that the session created by `agent.py` can access the authorized account and its tools.

### 7. Run the assistant

```bash
python agent.py
```

Enter a request at the `YOU:` prompt. Enter `exit` or `leave` to end the loop.

## Data handling

For each completed interaction, the application attempts to store:

- The user's prompt in `query`.
- The agent's final response in `response`.
- The database-generated creation time in `created_at`.

The current implementation stores conversation text in Supabase. Avoid entering passwords, API keys, or other sensitive information into the assistant. Decide on retention, access controls, and privacy disclosures before making this available to other users.

## Current limitations and next steps

The following are observations and suggested improvements based on the current source code; they are not claims that these features are already implemented.

- **Database ID generation:** Make the `id` column an identity column or otherwise generate IDs before inserting.
- **Authentication lifecycle:** Make the Composio authorization and agent session use the same intended connected account.
- **Dependency management:** Add a `requirements.txt` or `pyproject.toml` with tested, pinned dependencies.
- **Error handling:** Handle failures from the agent, Composio, and Supabase so one failed request does not unexpectedly terminate the session.
- **Input/output polish:** Fix the extra closing parenthesis in the current terminal response print statement.
- **Conversation retrieval:** Add a way to read previous chat history if conversation continuity is desired.
- **User identity:** Replace the hard-coded Composio user ID with a deliberate per-user identity strategy before supporting multiple users.
- **Security:** Define Supabase Row Level Security policies and keep credentials out of the repository.
- **Testing:** Add tests for prompt handling, database writes, and calendar actions.
- **Interface and deployment:** Consider a web interface and deployment only after the core agent and authentication flow are reliable.
